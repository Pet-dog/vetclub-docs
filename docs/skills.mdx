# Skills catalog

This public snapshot lists the 25 capabilities in the baseline task profile.
Task-specific skills are connected only when a task needs them and are not
part of this default catalog.

| Skill | Public summary |
| --- | --- |
| `skill-registry` | Finds available skills, resolves duplicate names, and selects the smallest relevant set for a task. |
| `critical-thinking` | Challenges high-risk claims and decisions against concrete evidence. |
| `research` | Verifies current or easily misremembered facts from primary sources and cites them. |
| `verification` | Runs the smallest meaningful check needed to support a completion claim. |
| `humanizer` | Rewrites supplied prose naturally while preserving facts, numbers, citations, and constraints. |
| `context-engineering` | Builds a focused evidence pack when project state or sources of truth conflict. |
| `semantic-code-navigation` | Uses structural code relationships for symbol, caller, implementation, and impact analysis. |
| `spec-driven-development` | Defines observable outcomes, boundaries, risks, and acceptance criteria before implementation. |
| `planning-and-task-breakdown` | Turns a clear contract into sequenced work with dependencies and stop conditions. |
| `api-and-interface-design` | Designs compatible API, schema, event, CLI, and module contracts. |
| `production-system-design` | Designs multi-component production systems from measured requirements and failure boundaries. |
| `incremental-implementation` | Delivers large changes as small end-to-end slices that remain testable and reversible. |
| `source-driven-development` | Grounds version-sensitive implementation choices in current official documentation. |
| `deprecation-and-migration` | Plans safe replacement, migration, and retirement of legacy behavior and consumers. |
| `engineering-copy-and-docs` | Produces precise technical documentation, diagnostics, help text, and machine-readable output. |
| `code-review-and-quality` | Reviews changes for correctness, tests, readability, architecture, security, and performance. |
| `doubt-driven-review` | Applies adversarial review to substantial claims before they become delivery decisions. |
| `debugging-and-error-recovery` | Finds root causes from evidence and restores a working path without guesswork. |
| `ponytail` | Chooses the smallest implementation that works: existing path, standard library, native feature, then minimal code. |
| `ponytail-audit` | Audits a repository for unnecessary dependencies, abstractions, wrappers, and dead flexibility. |
| `ponytail-debt` | Collects explicit Ponytail deferrals into a compact debt ledger without changing code. |
| `ponytail-gain` | Shows Ponytail's published benchmark impact as a compact scoreboard. |
| `ponytail-help` | Displays the available Ponytail modes, skills, and commands. |
| `ponytail-review` | Reviews a diff specifically for removable over-engineering and simpler native alternatives. |
| `VOR-skills` | Routes VetPilot work to the correct project owners and proportionate evidence checks. |

## What is deliberately absent

The catalog does not publish skill bodies, local paths, installation state,
source coordinates, repository identities, hashes, private instructions, or
task-specific packages.
